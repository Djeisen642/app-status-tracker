# Verifying the running app

The unit suite (`pnpm run test`) covers pure logic and proves nothing about
whether the app _runs_. A typo in `mustGet('empty')`, a listener wired to the
wrong element, or a CSS rule that overrides `[hidden]` all pass lint,
typecheck, tests and the bundle, and ship a blank window. The end-to-end suite
is what catches those.

## Run it

```bash
pnpm run e2e              # the whole suite, headless
pnpm run e2e -- capture   # just the screenshot captures
pnpm run e2e:ui           # interactive, for debugging a failure
pnpm run e2e:report       # open the HTML report after a failure
```

Then **look at the result**: `docs/screenshots/*.png` are regenerated by the
capture tests, in both light and dark. Read them. An assertion checks that
something rendered; only looking tells you it rendered _right_.

### If Chromium can't be downloaded

If _every_ spec fails in a few milliseconds, that is a missing browser, not your
change. Sandboxes and CI images often ship a Chromium but block Playwright's
download. Point at the existing binary:

```bash
PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium-<ver>/chrome-linux/chrome pnpm run e2e
```

(`ls /opt/pw-browsers` for the version.) Do **not** run Playwright's browser
installer (`pnpm exec playwright install` or `npx playwright install`) in a
sandbox: it fails on the network after several wasted minutes.

## Why a browser can test a desktop app

`src/lib/tauri.ts` guards every native call behind `isTauri()`, so the browser
runs the _same_ controller and rendering as the desktop build.

**What this does not cover**, and cannot: the tray icon and its click, the tray
menu, window positioning, always-on-top, and native dialogs. Those need a real
desktop. Never report them as verified on the strength of a green e2e run. See
"Known unknowns" in `docs/future-work.md`.

## Writing a new case

`e2e/harness.ts` does the setup. `startApp(page, options)` freezes the clock and
starts from empty storage. When there is state to seed, seed it through the same
`localStorage` keys the browser build uses: **no test-only hooks in the app
itself**.

## Checklist for "does this change work?"

1. `pnpm run check`: format, lint, typecheck, version agreement, unit tests.
2. `pnpm run build`: it bundles.
3. `pnpm run e2e`: it runs.
4. Look at `docs/screenshots/`.
5. In `src-tauri`: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
   `cargo check`, `cargo test`.
